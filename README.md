# 对话内图片生成

## Codex CLI

在“设置 → 模型”中配置 Codex CLI 连接并登录。然后打开“插件 → 图片生成 → 设置页面”，将生图渠道设为 Codex CLI，并选择连接和执行模型。聊天可继续使用任意支持插件工具的模型；`image_generate` 会独立调用所选 CLI 账户，不需要 OpenAI API Key。也可以在对话中直接选择 Codex CLI 模型使用其原生生图能力。

独立生图创建可保存的独立 CLI 线程，不改变聊天模型或已有 CLI 会话绑定。同一个 CODEX_HOME 下可在 Codex 历史中检查任务；隔离登录连接的历史在该连接专用目录。生图总等待上限为 10 分钟，终止错误会立即显示，不自动重试。宿主在 connections/image-jobs 保存不含提示词或图片字节的阶段记录，包含 threadId、turnId 及错误。宿主把经过校验的项目图片或当前对话附件复制为只读参考输入，完成或失败后清理临时文件。CLI 的尺寸和质量作为提示偏好传入，不能保证严格执行。Codex CLI 需要自行提供内置生图能力与可用账户额度。

CLI 完成生图后，宿主校验并保存原图到 `generated-images/<唯一编号>/`。正文显示交互点阵等待卡片，收到真实结果后显示图片预览，不随工具详情折叠。图片支持放大、下载和再次编辑。再次编辑只填入输入框；用户提交后，已保存图片作为参考图转发给所选生图渠道。失败或缺失结果显示错误，不自动重试，也不回退到 API。

Codex CLI 需提供内置 image generation 能力。宿主接收协议中的内联图片结果，或已授权项目内的保存路径；不会读取 CLI 返回的任意项目外路径。自动测试使用模拟 CLI 事件，真实账户生图尚未验证。

## OpenAI 图片 API

在插件设置中打开“图片生成”，选择独立的生图模型并保存 OpenAI API Key。密钥由桌面宿主使用操作系统安全存储加密，普通插件配置、工具参数及结果不包含密钥。接口固定为 OpenAI 官方地址，网络沿用产品代理，没有自动供应商切换。

在项目对话中提出生成要求。工具通过正常权限及审批链路调用一次付费接口，不自动重试。文字生成使用 generations；引用图片时使用 edits。首版支持 gpt-image-1、gpt-image-1-mini、gpt-image-1.5 和 chatgpt-image-latest。最多引用八张 PNG/JPEG/WebP，每张不超过 25 MiB。引用可以是已授权项目相对路径，或者当前对话内附件的 `attachment:<id>`。宿主会校验文件类型、实际解码、路径和附件来源。

原始 PNG 和生成元数据保存至项目 `generated-images/<唯一编号>/`。对话历史保留图片内容，可放大和下载。“再次编辑”把图片路径加入当前输入框，由用户补充修改要求后提交，继续走正常工具审批，不直接发起付费请求。

## 验证步骤

自动化验证使用模拟供应商及模拟系统加密接口，不等同于真实生图。浏览器组件测试已覆盖放大、关闭、原始字节下载、再次编辑引用事件及重新打开。真实 OpenAI 请求、操作系统加密和完整桌面链路仍需产品内端到端验证。

1. 打开设置，保存密钥，确认显示“凭据已配置”；重新打开仍显示该状态，密钥输入框为空。
2. 在项目对话中请求生成一张图片，在正常审批流程中单独批准付费调用。
3. 确认图片展示，项目目录包含原图和 metadata.json；放大并下载原图。
4. 点击“再次编辑”，补充具体修改，确认按钮仅填入草稿；提交并单独批准后检查新产物不覆盖前一张。
5. 使用当前对话上传的图片或项目内参考图发起编辑，确认引用能被校验和读取。
6. 重启产品并打开历史，确认图片仍可查看和保存。
7. 清除凭据后再次请求，确认明确提示先配置凭据，没有伪成功图片。超时或网络失败可能仍被供应商计费，不应盲目重试。

协议依据：[OpenAI 图片生成接口](https://developers.openai.com/api/reference/resources/images/methods/generate)、[图片编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit)。首版有意只支持上述模型及声明的尺寸、质量参数。
